# RESIDUAL WITNESS DISCRIMINATOR 001

## Status

This slice adds a second discriminator specifically targeted at a witness path challenged by contact #1.

The first contact remains immutable history.

The second contact does not appeal, overwrite, or replace it.

Flow:

```
original witness field
→ contact #1
→ non-destructive WORLD update
→ residual challenged path
→ Dogram residual discriminator
→ NAV proposal
→ explicit admission
→ contact #2
→ WORLD two-contact history update
```

## Core laws

```
SECOND CONTACT ≠ REVISION OF FIRST CONTACT.
RESIDUAL TENSION ≠ RESET.
REPEATED CHALLENGE ≠ WITNESS ERASURE.
SECOND SUPPORT ≠ FINAL VERDICT.
```

## Residual target

The first WORLD update preserves:

- one contact-supported relation
- one or more challenged relations
- all original witness addresses

A residual discriminator must bind to:

- the exact original field
- the exact first WORLD update
- the exact first contact
- the prior supported relation
- one relation that was explicitly challenged by contact #1

It cannot retarget an aligned path and call that residual testing.

## Structural minimization

Residual candidates retain the same bounded cost grammar:

```
irreversible_steps = 0
world_contacts = 1
changed_variables >= 1
external_dependencies >= 0
```

Dogram selects the minimum declared structural cost.

The candidate must predeclare two distinct outcomes:

- the prior-supported relation repeats
- the challenged relation reproduces

## Separate authority

Contact #2 receives its own:

- Dogram transition
- NAV reorientation proposal
- explicit local admission
- ordinary NAV orientation receipt
- ordinary NAV contacted receipt
- residual contact capsule

Authority from contact #1 cannot silently carry forward.

## Two possible residual outcomes

### Challenged path survives

If contact #2 matches the predeclared challenged relation:

```
residual_tension_status = challenged_path_survives_second_contact
```

The historical relation set now contains both contact-supported paths.

This does not invalidate contact #1.

It establishes that sequential contacts support different live relation paths.

### Challenged path is challenged again

If contact #2 again matches the relation supported by contact #1:

```
residual_tension_status = challenged_path_challenged_again
```

The challenged witnesses remain present and addressable.

They are not deleted or converted into false witnesses.

## Contact history

The WORLD residual update carries exactly two distinct contact addresses:

```
contact_history_sha256s = [
  contact_1,
  contact_2
]
```

It hard-codes:

```
first_contact_promoted_to_verdict = false
majority_rule_used = false
verdict_status = withheld
all_witnesses_retained = true
```

Every witness receives a two-contact history:

- original relation
- first contact state
- second contact state

## Hostile controls

The tests require that:

1. the minimum residual discriminator is selected;
2. the residual candidate targets a relation challenged by contact #1;
3. contact #1 remains addressable through transition, admission, contact #2, and WORLD return;
4. contact #2 requires separate explicit admission;
5. its observation must match a predeclared outcome;
6. the challenged path may survive contact #2;
7. the challenged path may be challenged again without erasure;
8. contact #2 may oppose contact #1 without rewriting it;
9. original field and first WORLD update remain unchanged;
10. witness count never changes;
11. majority inversion cannot change residual status for the same contact sequence;
12. contact #1 cannot be promoted to verdict;
13. witnesses cannot be deleted;
14. the first contact cannot be dropped from history;
15. mutation of contact #2 breaks the history chain;
16. inspection claims neither truth nor rewritten history.

## Result

The system can now represent a stronger form of corrigibility:

```
CONTACT #1 SAYS A
CONTACT #2 SAYS B
```

without forcing:

```
B REPLACES A
```

and it can also represent:

```
CONTACT #1 SAYS A
CONTACT #2 SAYS A AGAIN
```

without forcing:

```
B-WITNESSES ARE DELETED
```

The history accumulates.

Authority does not.

## Claim limit

Both contacts are executable contract specimens using supplied fixture observations. The runtime verifies that each observation was predeclared, but it does not establish external execution or substantive truth.
