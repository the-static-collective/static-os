# STATIC-2012-001 — reference machine

Status: candidate contract; **not physically device-tested**.

STATIC 2012 asks:

> Can the Static Collective make an old computer more interesting instead of merely making it feel obsolete?

Reference target: 2012-era amd64, 2 cores minimum, ~4 GiB RAM floor, 8 GiB comfortable, 32 GiB free disk floor, 80 GiB comfortable, integrated graphics accepted, no GPU required for core sovereignty, network required for initial sync, and network optional for ordinary continuity after sync.

These are test-envelope numbers, not a claim that a physical 2012 machine has passed.

## Constitutional inversion

The machine does not need to perform every expensive operation. It must retain the parts that make the operator sovereign:

```text
receive → verify → hold → inspect → compose → choose → dispatch → remember → cross → resume
```

Heavy rendering or modern model inference may be external instruments. Decision, provenance, artifact address and local admission remain local.

```text
OLD HARDWARE != THIN CLIENT
LOCAL SOVEREIGNTY != LOCAL HEAVY COMPUTE
DISPATCH != AUTHORITY
```

## Capability board

**GREEN** is required local core: First House entry, content addressing, reLATTE crossings, GrO lineage/checkpoints, TranchNode bounded memory, Dogram bounded verification, and GHoT Instrument Rack control.

**YELLOW** remains locally meaningful with degradation: Toaster editing, Blender possibility composition, and Full Measure frontier projection may use proxies, reduced resolution, simplified effects, or deferred render.

**BLUE** is dispatchable: high-resolution rendering, modern AI video, and large-model inference may be performed by another opted-in instrument while evidence and admission remain local.

**RED** is deliberately unavailable. The first RED item is autonomous execution of discovered capabilities: discovery never grants authority.

## Named-bottleneck law

No feature may merely say “needs a better computer.” Every non-GREEN capability must declare:

```text
resource bottleneck + evidence + lawful fallback
```

The validator enforces this.


## Self-audit

```bash
python3 scripts/validate-static-2012.py profiles/static-2012.json
python3 scripts/static-2012.py profiles/static-2012.json
```

The assessor reports visible hardware facts, floor checks, `reference-ready` / `comfortable` / `below-floor`, the capability board, and explicit non-claims.

A 2-core / 4 GiB / 48 GiB fixture is tested as `reference-ready`; an 8 GiB / 120 GiB fixture is `comfortable`. This is contract verification, not a benchmark.

## Offline posture

After initial sync, ordinary continuity is required to remain network-optional. Local work may accumulate as crossings, receipts, held items, artifacts, descendants, wants and outbox material until a road returns.

This slice does not yet implement a universal outbox daemon.

## Relationship to First House

STATIC 2012 stacks on the green First House desktop candidate. It does not change First House claims: physical install remains unverified; offline-after-install remains pending device test; no bootable-ISO claim is added; no external project is silently downloaded on launch.

This is a reference-machine contract and explicit loadout planner, not an automatic mega-installer.
