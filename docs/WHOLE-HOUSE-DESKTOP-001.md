# WHOLE-HOUSE-DESKTOP-001 — pinned integrated Workbench candidate

This is a **draft desktop-app packaging composition**, stacked on STATIC OS Launchpad desktop installer PR #6. It does **not** install the STATIC OS live ISO or establish a bootable operating system.

## Source and ownership

- Workbench integrated candidate: [FIRST-USE-WHOLE-HOUSE-001](https://github.com/the-static-collective/static-workbench/pull/65). Pin only its **final exact, green** source head across `manifest/genesis-001.json`, `interop/flight-003.json` and `interop/triad-001.json`.
- Workbench owns HOUSE, project/branch discovery, source-bound Creator Desk, creative proposals/saves, local receipts, and its first-use Flight Board.
- STATIC OS owns the host bootstrap, frozen desktop package, ISO build recipe, source pin and OS/distribution gates. Launcher installation never grants OS/agent/project execution permission.
- The prior experimental Storyship/TranchNode references and Corpus/Jubilee reference contracts remain reference-only. A copied module, manifest or checksum is not proof of runtime interoperability.
- Existing configuration, journal, project files and source checkouts must survive install, restart, upgrade and uninstall.

## What the human should see

1. Install the *verified compatible* desktop Workbench package and choose Static Workbench from the applications menu.
2. In HOUSE select **Start using Workbench**. The first-use Flight Board opens available local desks and shows which optional neighboring organs are actually observed on disk. The board does not run those projects.
3. Use Creator Desk's new saved-source Context Door to preview Follow/Contrast, explicitly apply a proposal to an empty new draft, write and save. Reopen the saved draft after restarting the app; optionally compare against ARK/ARRIVAL's read-only local re-entry pointer.
4. Use Branch Deck, Attention, Native Maxhinal and Return Desk individually with their own review/effect boundaries. L BRANCH Python remains a reference-only research capability.
5. The STATIC OS ISO and manual ELF gates remain separate unverified research/VM stages; installing Workbench advances none of them.

## Candidate release gates

- Workbench integrated head has exact-head Python pytest, Node/JS, Dogram and Static Live integration smokes green. An earlier green head does not qualify a later source pin.
- STATIC OS exact HEAD passes manifest, TRIAD, FLIGHT-003 and desktop package workflow; built artifact records pinned SHA, runtime closure and SHA-256, while publisher authentication/reproducibility remain unproven.
- Confirm the receiving Zorin major version / architecture. Existing #6 package is intended for Zorin 17+ or Ubuntu 22.04+ amd64; an older Zorin install is not certified.
- On a disposable or backed-up actual supported Zorin machine, test GUI install, first open, browser, keyboard, smaller screen, repeated click, service port conflict, logout, restart, journal/SQLite backup and restore, upgrade and uninstall. No unattended disk modification.
- Complete independent disposable VM ISO boot, offline HOUSE, manual guest ELF and recovery checks before making any STATIC OS bootability claim.

Never present a generated `.deb` as an already-installed app or a build-success message as hardware certification.
