## The executable part

The new module instruments/field_processor.py implements the unchanged host interface:
- describe: validate a finite explicitly synthetic source; bind its raw SHA256 without publishing a private local path.
- observe: exclude nonconsenting, revoked and expired sessions; produce content-addressed bounded candidate evidence rather than raw room recordings.
- select: interpret the existing ELEVEN-HEAP address and offer a single read-only candidate; NEVER admit, connect, transmit or actuate.
- host integration: existing InstrumentHost remains in control of admission, replay, durable events, source changes, withdrawal, and distinct owner-local reLATTE operations.

## Physical computing threshold

Three progressively stronger hypotheses deserve distinct tests.

1. FIELD AS SENSOR: a microphone, geophone, light receiver or copper probe provides observed measurements. This is measurement, not proof of an environmental processor.
2. FIELD AS CIRCUIT: a physical substrate gates, shapes or routes a signal, with measured losses, condition dependence and stability. This is a physically demonstrated transfer function if controlled tests reproduce it.
3. FIELD AS PROCESSOR: the physical substrate measurably computes a needed operation or maintains consequential state in the overall program, beyond a passive sensor value. Compare independently against a software-only baseline and an inert physical control. Record power, noise, repeatability and failure cases.

The field processor **already performs real finite software computation** over simulated inputs. It does not yet demonstrate ambient matter doing computation.
