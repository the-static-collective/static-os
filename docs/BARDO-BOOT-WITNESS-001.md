## Exact-byte custody result

During the bounded host execution, the same SHA-256 was observed at SOURCE, DISPATCH, BARDO_HOLD, CORPUS_ADMIT, and REOPEN_VERIFY.

The temporary Bardo runtime was then deleted. No persistent `organs/supabardo/` interior was created. Corpus retained the bytes; TranchNode retained the ancestry pointer; the durable crossing export retained the signed history.

A second boot occurrence reopened the same host root with a distinct boot identity and rehashed the Corpus object to the original source hash.

## Claim boundary

This witness proves a host-level root reopen over the exact selected image bytes. It does **not** prove:

- a real process restart;
- a VM cold boot;
- a physical power cycle;
- a live Supabase/SupaBardo membrane crossing;
- a second live membrane crossing;
- satisfaction of the SupaBardo extraction gate.

The source pixels are also **not vendored in this Git branch**. The repository contains their cryptographic address, observed byte length, signed crossing/receipts, and the bounded execution evidence. Rechecking the source bytes themselves therefore requires the external original.

That limitation is deliberate and machine-checked so the witness cannot silently become a stronger claim than the occurrence earned.
